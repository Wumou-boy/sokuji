# AED Translator V0.3.0-beta.3 Windows 试用记录

本版以 Sokuji 0.51.2 为基线。验证机运行 Windows x64。以下样本均为合成语音，未采集公司会议内容。

## 账号与费用归属

在线和面对面的 Qwen 翻译均可使用普通 API，设置里可以选择大陆、国际或百炼公司工作空间端点。纪要另选服务。选择百炼纪要时，个人共享端点使用个人 Key，公司工作空间需要自己的地址和 Key。工作空间地址或密钥缺失时停止调用。保留已保存的纪要模型。团队 Token Plan 不在本版接入范围。

在本机已有的个人百炼配置下，`qwen3.8-livetranslate-flash-realtime` 返回了字幕及译音，`qwen3.8-flash` 对合成会议文本生成了一个议题。公司工作空间通过模拟传输检查了地址、凭据选择及失败处理，公司账户的权限、网络与账单仍需使用实际工作空间验证。

## 本地分人与三语字幕

设置里的「本地说话人识别」适用于 Qwen 自动轮次。在线会议可给远端混音或我方共用麦克风编号，面对面可给一支麦克风里的多人编号。识别不确定时保留“说话人未确定”。CAM++ 模型约 28 MB，可以下载，也可以在通用设置导入通过校验的 ONNX 文件。

第一轮面对面实测使用个人 API 和打包程序。四种合成声音在 174.2 秒里说了 30 句，涵盖中、日、英。选择中、日两种目标字幕时，程序收到全部 4,180,896 个输入采样，得到 29 条完整字幕。第 12、13 句匹配到同一时间区间。按时间交叠比对，24/30 个原始发言获得正确的匿名编号，6/30 未确定，共出现四个编号。该比较用时间区间和编号确认分人，不能衡量译文准确度。

单独测试打包的 CAM++ Worker 时，给定正确的每句起止点。第一组 30 句中 20 句编号正确、10 句未确定，第二组 25 句中 17 句正确、8 句未确定，两组都没有错归。55 次推理的中位数为 188.5 毫秒，P95 为 226.1 毫秒。这里计时仅包含声纹推理，公司 16 GB 办公本仍需现场测量。

第二轮选中、日、英三种字幕，同一组音频通过个人百炼重放。Windows 窗口实际显示 29 行，每一行都能读取到三种语言的非空文本。按原文顺序与脚本逐句对照，第 12、13 句（先日语、后中文）被合并，另外 28 句可以一对一匹配。28 句中原语种标对 27 句，1 句未确定。匿名说话人编号标对 22 句，6 句未确定，共出现四个编号。合并行保留原文和三种语言，其原语种也显示未确定。三列都有文字不能说明每个译词都正确。

## 译音和在线会议收音

同一段 4 秒合成录音通过普通百炼 API 发送，计时从开始送音频到收到首个译音 PCM。每种一轮，数据只作这次网络与录音条件下的观察。

| 译音方式 | 首个译音 | 生成的音频时长 |
| --- | ---: | ---: |
| 预设 Tina | 1.41 秒 | 2.24 秒 |
| 已登记的固定音色 | 1.38 秒 | 2.88 秒 |
| 每轮复刻 | 2.38 秒 | 4.08 秒 |
| 只复刻首位说话人，首次发言 | 2.41 秒 | 4.16 秒 |

Windows 自动选源实现在收到 Teams 会话电平后验证进程 PCM。进程拿不到音频时，只有可将输出端点归到该会议的情况下才回退。同一端点有另一应用同时发声时，暂停混合音频转发。安静的 Teams 后台进程允许 Auto 选择实际有声的其他会议应用。

WebRTC AEC3 WASM 在合成双讲样本中将远端残响压低 24.9 dB，近端语音相对输入衰减 1.7 dB。实际公司 Teams 的零音量旁听、开外放双讲及远端语音误触发我方译音次数仍需现场确认。

在线会议另测了「对方音频」与「我方共用麦克风」。生产适配器两路各输入 30 句合成 PCM，模拟服务返回流式文本和可控声纹向量。两路均把 30 句的说话人标签和主译贴回了对应原文。这项回归能发现晚到结果贴错行的问题，现场分人准确率仍须用真实会议测量。

## 会后和安装

桌面会话沿用本机历史。面对面的正式会话存原文、目标字幕及可用的说话人编号，合成回放不写入个人历史，也不自动发起纪要。SQLite 用 121 条三语字幕验证了超过界面显示上限后的首尾内容、修订和关闭重开。会后纪要仅在用户已开启、正常结束且本地归档完整时触发。

将 Windows x64 压缩包解压到一个目录，打开 `AED Translator.exe`。应用沿用同一 Windows 用户的原有配置。需要排查音频时，可从该目录运行 `AED-Audio-Report.cmd`。

最终交付的 EXE 又通过个人百炼重放了 7 句，7 行均有三种字幕，并再次生成了一份测试纪要。使用独立的新配置启动同一 EXE，OpenAI、Qwen 和公司工作空间三项凭据都为空。选「面对面对话，只要字幕」后可直接进入三语界面。原 Windows 配置的交付版也已单独启动。

本轮 162 个相关测试文件的 2,102 项用例通过。全仓 TypeScript 检查仍有 93 条诊断，与已有 beta.2 日志对照没有新增诊断种类。Windows 交付包已检查用户配置文件及常见凭据格式，并校验压缩包 CRC，以及包内主程序、app.asar、测试 CMD 和本记录与交付目录的内容一致性。
