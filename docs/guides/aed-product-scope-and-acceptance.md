# AED Translator 产品范围与验收清单

2026-11-27 · 产品梳理稿 · Windows 桌面版

AED 要让员工在原有会议软件或同一间会议室里，听懂中、日、英发言。在线会议还要把我方译音交给对方。员工可以自己装包、配置服务、开会、回看用量，并用一份诊断报告说明出了什么问题。

本清单从 AED `0.3.0-beta.2` 开始编写，依据试用反馈、邮件《翻译的反馈》和 Windows 工作树制定。上游 Sokuji 基线为 `0.51.2`。下文保留当时的缺口和验收条件。本轮 Windows 测试版的实测结果见 [V0.3 beta.3 验证记录](aed-v0.3-beta3-verification.md)。[版本定义](../../package.json) · [原 V0.3 技术计划与预览记录](aed-v0.3-plan.md)

## 一、从员工实际怎么用出发

| 场景 | 打开 AED 后应该得到什么 | 最容易判断错的地方 |
| --- | --- | --- |
| 一人用笔记本开 Teams，开外放 | 可以先开 AED 再入会。对方说话时看流式双语字幕，我方说话时对方收到选定语言的译音；两人同时说也能保住我方发言。 | Windows 显示 Teams 有电平只能帮助寻找音源。还要分别证明 AED 收到了对方的数字音频、麦克风里的外放回声得到抑制、译音没有再进入捕获。 |
| 会议室主电脑负责收音和外放，个人电脑只看字幕 | 个人电脑加入 Teams 会议音频，关本机麦克风和物理监听，也能看到远端原文、译文。无需为看字幕额外出声。 | 物理音量为零、设备被禁用、Teams 自身音量为零、根本未加入会议音频，是四种条件。最后一种应说明如何接入，前三种要在真实设备上分别记录。 |
| 戴耳机，或用浏览器及其他会议软件 | 同一入口。自动选源能跟随开会、短暂停顿、换设备；我方开口正常，耳机下不削掉轻声或句首。 | 浏览器有声仅能验证浏览器路径。端点混音中有通知或另一应用说话时，要能看见来源不确定，并避免将无关声音送去翻译。 |
| 面对面，一台电脑放桌上 | 选两种字幕语言即可开始，需要时再加第三种。翻译服务和麦克风沿用在线会议的设置。两人或多人轮流说，应用逐句显示原文、译文和可用的匿名说话人编号。 | 一支麦可以有多人，同一人也能换语言。面对面的核心使用流程无需 Teams、虚拟线缆、甲乙角色或译音设置。 |
| 会后回顾、换版本、排查问题 | 在历史里查到这次会话及 Token。按选定服务生成纪要。更新后沿用设置和凭据。遇到故障只需运行一次诊断并返回一份 TXT。 | 保存了用量不等于保存了完整字幕；一次合成样本跑通也不能证明公司电脑上的 Teams 已可用。 |

## 二、两种模式共用哪些能力

**一条发言需要分别记录四件事：音频从哪一路来、这一段是谁说的、实际用了什么语言、用户要读哪些语言。** 例如 Teams 远端同事先用日语、再用英语，两句都可以标为「对方 · 说话人 2」，各自保留原文，中文译文跟在对应句下。我方改为向对方发送日语，只改变之后我方发言的译音目标。面对面可以产生相同的字幕记录，但来源是一支现场麦克风。

| 能力 | 共用的产品要求 | 在线会议特有 | 面对面特有 |
| --- | --- | --- | --- |
| 收音与会话控制 | 明确显示在等音源、已收音、服务连接中或已中断。停止时释放设备和连接。 | “我／对方／两者”选择采集方向。Auto 显示实际应用、实际采集路径和电平；系统混音回退应可辨认。 | 一支麦克风，启动就能看见输入电平。会议界面关闭我方麦克风后，仍能独立开始现场收音。 |
| 中日英识别与目标语 | 按发言识别语种，保留原文，逐句决定哪些目标需要译。语言切换不改变说话人。 | “对方说”可自动，“我阅读”与“对方听到”单独设置。译音始终有明确目标；会中切换按下一句生效，已开始的句子保留原目标。 | 两个不同的字幕语言加一个可关闭的第三字幕语言。若只选中英而有人说日语，建议仍保留日语原文和所选两种字幕；当前界面已有显示额外原文的逻辑。 |
| 说话人编号 | 设置里一处可选，按会话匿名分人，允许“未确定”。已有成员标识可作为线索；语种、声道和已注册的合成音色均不充当身份。 | 本机麦可能有多人，Teams 远端的混合流也可能有多人。用“我方／对方 + 编号”保持来源清楚。跨设备重复收到同一句时先解决串音。 | 同一麦内按人编号，无需先选甲乙。切换语种、长时间暂停后再开口时重点检查同人是否被拆开。 |
| 流式字幕与阅读 | 原文与译文用同一条发言标识；临时字幕逐步更新，定稿替换同一行，补译失败保留原文。紧凑排列，默认跟随最新；手动上翻后可留在原位并返回最新。 | 我方、对方互不覆盖。尤其验证对方连续说长句时能在句末前看到文字和主译文。 | 同条依次放原文及所选译文，避免重复原文。主字幕、第三字幕各自显示进度；定稿后才能补的目标要区分出来。 |
| 译音与音色 | 与输入侧的身份识别独立。 | 预设、实时复刻、首位说话人复刻、已登记的固定音色分别验证。原音直通音量、本机“我也听”、发给对方的译音各走各的路。固定音色录制有朗读文本、电平、试听和明确关闭操作，标出所需端点及所属账号。 | 当前需求只要字幕，使用者不必配置或付费生成译音。 |
| 历史、纪要、用量 | 同一次会话可以关联字幕、用量和可选纪要。Token 每次从零开始，按活动和可用的服务回报归集。 | 保留方向、多说话人、原文和目标语。查错时可以将“对方内容被译回”定位到具体输入方向。 | 建议复用同一历史入口，保留说话人、语种及第三字幕；保存范围沿用用户已选策略。该能力还缺完整的写入、重启、回看验证。 |

相关入口见[面对面界面](../../src/components/FaceToFace/FaceToFaceMode.tsx)、[面对面设置与字幕状态](../../src/stores/faceToFaceStore.ts)、[Qwen 在线方向配置](../../src/providers/qwen_livetranslate/config.ts)与[会话 Token](../../src/lib/usage/sessionTokens.ts)。

**设置应该放在哪里**

- **所有模式共用**实时翻译服务及其端点和凭据、我方麦克风、字幕显示偏好、本地分人开关、模型缓存与诊断入口。在设置里更换翻译服务或麦克风后，两种模式都使用新的选择。面对面的字幕语言单独选择，纪要服务与实时翻译也分别选定。
- **各模式分别记住**在线的收音方向、远端来源、读写语种、译音和监听路由，以及面对面的字幕语言组合。上次面对面选了第三种语言，下次在线会议的译音目标仍取在线设置。
- **每次会话重新开始**说话人编号、临时字幕、滚动位置及实时 Token；历史按会话标识归档。换麦或服务重连时应清楚显示中断区间，同一轮补发字幕需要去重。切换模式遇到活动会话时先明确是否结束本场，避免意外继续收音或扣费。

## 三、当前实现到哪里，下一步缺什么

| 工作项 | 截至本次盘点的证据 | 下次开发或验收要解决的问题 |
| --- | --- | --- |
| Teams 数字收音与选源 | V0.3.6 默认采集系统声音；之前选了自动的配置升级时使用系统声音。也可手动指定应用或播放设备。 | 检查同一场会议的对方字幕与原声；系统采集也包含同时播放的其他程序。[Windows 采集](../../electron/windows-audio-utils.js) |
| 笔记本外放与虚拟线缆 | V0.3.6 恢复上游的麦克风回声消除设置，移除 AED 自定义补偿。在系统播放设备为扬声器时，在线会议页提醒使用耳机。 | 用耳机复核双方说话时的字幕和译音。外放时麦克风可能收到对方的声音。会议麦克风可选配对的 CABLE Output。 |
| 双语、第三字幕与长段 | 工作树已有两个主字幕选择和独立第三语言选择。面对面 Qwen 主目标流式，其他目标需要时重放有界音频；OpenAI 主目标实时，额外译文可在原文定稿后补齐。邮件报告过 30 秒区间错误和重放超时。 | 30 秒以上长句、短句快切、语种切换、时间戳缺失、重连分别测首原文、首译文、定稿；额外译文迟到挂回原句。检查断句不丢词、不重复收费。只生成缺少的目标，新增文本模型调用要显示路线及用量。[面对面运行时](../../src/lib/faceToFace/runtime.ts) |
| 可选本地分人 | 云端对照中 4 个合成声音说 30 句，上游给出 26 个编号。本地 CAM++ 办公样本有 4 人 25 句，按真实人对齐，21 句归对、4 句未确定；该样本未见错归。应用工作树用 ONNX Runtime/WASM；当前在线接入仅覆盖 Qwen 对方自动轮次且开启说话人标签，面对面有 Qwen 路径。 | 接入点应属于会话层。先测两种模式、多声源和本机共麦，再决定哪些组合可对用户开放。原生参考测量不能代替打包应用、16 GB 办公本、真实人声实测。模型约 28.3 MB，首次下载、无网、缓存损坏或识别失败时也应能继续看字幕。[模型定义](../../src/lib/faceToFace/speakerModel.ts) · [推理 Worker](../../src/lib/faceToFace/speakerEmbedding.worker.ts) · [在线接入条件](../../src/providers/qwen_livetranslate/config.ts) |
| 译音性能与语速 | 固定音色已有注册和删除接口，用户听辨能够认出自己的声音；不同 Qwen 连接方式提供的音色选项不同。 | 同一句话测预设、首人复刻、逐次复刻、固定音色，记首段译音和末段播放结束。长句积压要拆开看模型何时开始输出、何时生成完、播放队列余量。语速调节先做可懂度和赶上进度的实验。[固定音色接口](../../src/providers/qwen_livetranslate/voiceEnrollment.ts) |
| 会后记录与费用归属 | 在线历史有本机数据库、导出和回收站。面对面界面只保留最近 100 条显示记录，需要从历史另行验证全文。新 Qwen 桌面配置的纪要默认选百炼。 | 核对两种模式结束、异常中止、重开后的历史。纪要走普通 API。个人百炼共享端点用个人 Key，公司百炼工作空间用公司的地址和专属 Key。缺少公司配置时在该路线上报错。先用个人 API 验证，公司采购另行决定。服务未报告用量时显示未知，以服务商账单核对费用。[历史结构](../../electron/history-schema.js) · [纪要默认逻辑](../../src/lib/notes/notesService.ts) · [用量汇总](../../src/lib/usage/ledger.ts) |

本地分人两项现有证据分别保存在工作目录的 `out/face-speaker-benchmark/speaker-report.json` 和 `out/face-speaker-benchmark/local-office/native-assignments.json`。两组样本和推理链不同，不宜用二者计算产品准确率提升。打包版尚缺完整逐句得分。旧 V0.3 计划写的是“三语预设”，本清单按后续反馈采用第三个字幕语言选择；旧计划中的“本地分人待评估”也需结合上述工作树进展理解。

## 四、公司使用所需的设置、数据和交付

| 范围 | 已有基础与产品取舍 | 交付时怎么判定 |
| --- | --- | --- |
| 服务、网络、凭据 | 实时翻译优先 Qwen 3.8，保留 OpenAI 选择及内网 OpenAI 兼容端点的适用能力。两模式可共用**同一个服务、同一个账号**的已保存设置；Qwen、OpenAI、自定义端点之间各用自己的凭据。兼容文本接口能做纪要，其语音能力需要单独验证。 | 设置中按实际端点标“中国大陆”“国际（限支持地区）”或“自定义／内网”。检查项显示所选端点；区分网络握手失败、凭据或权限失败、某一模型不可用。当前 QwenCloud 有地区识别、百炼有共享／工作空间选项，仍需核对 UI 标签与实际路由一致。按邮件场景测试两模式手动选择 Qwen 或 OpenAI。[端点定义](../../src/providers/qwen_livetranslate/endpoints.ts) · [账号设置](../../src/components/SettingsPage/AccountsCategory.tsx) |
| 路线与本地模型 | 既有同样本对照中，Qwen 3.8 和团队 Audio 3.0 首个双语块中位数分别为 2.149 秒与 4.586 秒，各 3 次。另有 CPU 资源限额及 RTX 并发模拟。保留普通笔记本可跑的必要模型、按 PGX 能力筛选的内置候选，以及连接内网服务的入口。 | 限额桌面机结果标“本机模拟”。真实办公本测 CPU、内存、首字幕、发热后稳定性；真实 PGX 如需推广，再测通过内网的并发与排队。模型目录展示 PGX 候选即可，启动应用无需扫描实际 PGX。个人按量、团队计划、本地推理三者分别说明。[三路线对照](../../benchmark/meeting-translation-three-way/README.md) · [当前模型目录](../../src/components/SettingsPage/ModelsPage.tsx) |
| 会话数据与保密 | 收音发给选定语音服务；云端纪要需发送相应文字；固定音色注册会提交用户确认的样本。历史与诊断另有本地存储。现有通用凭据路径使用 Electron 的本地存储，本文未验证系统级静态保护。 | 列清何时发送什么、发给谁、保存在何处及怎样删除；保留用户已有选择。诊断默认排除密钥、原始音频和会议正文。公司是否批准特定云端点处理会议资料，交由公司按实际账号和条款判断。录音留存策略如需变更，另行确认。[设置持久化](../../src/services/SettingsService.ts) · [历史设置](../../src/components/SettingsPage/HistoryCategory.tsx) |
| 单一应用与轻量化 | Windows 应用名 AED Translator，上游归属和许可证保留在仓库与分发材料。AED 自有版本独立递增，沿用正常配置 `%APPDATA%\Sokuji`。保留可用于反馈的本机构建标识；既有需求要求去掉上游更新检查与相应界面。 | 同一包分别走旧用户升级和全新配置，两者都从正式可执行文件启动。升级后保留原密钥、音色引用、语种、设备和历史；新用户首次启用时只见自己的设置。检查解压后的包不含开发者资料、模型缓存、录音或密钥。轻量化先量安装包、解压体积、启动耗时、空闲内存，核对删依赖后所选功能仍可用。[桌面启动](../../electron/main.js) · [第三方说明](../../THIRD_PARTY_NOTICES.md) |
| 自助诊断与智能体 | 已有主动开启的本机 agent 控制、脱敏状态、设备和音频探测、字幕诊断及用量读取。当前 CLI 的标准在线启动路径有方向限制。 | 优先复用现有控制入口；缺哪个观测量就加哪个。单人 CMD 在当前版本和原配置上运行，输出一份 TXT。报告可定位“选到哪个源 → 有无真实音频 → 有无播放参考 → 有没有发给服务 → 字幕或译音到哪一步”。付费云探测和包含正文的导出分别由用户主动触发。[智能体命令与边界](agent-control.md) |

## 五、开发顺序与可复查的验收

下表是建议的交付顺序。已明确的使用场景先做；要不要扩大支持的服务、默认留存哪些面对面数据、是否发布语速选项，分别取决于实测和用户选择。

| 顺序 | 同一轮要做完什么 | 验收证据 |
| --- | --- | --- |
| 1 · 建立共同基准 | 统一两种模式的发言记录、时间戳与错误分类；为同一段三语录音保留人工答案。先跑现状作对照。 | 每句标明真实说话人、实际语种、目标语、起止时间，测试表有总句数。记录音频输入、第一段原文、第一段主译文、其他译文、定稿、译音首尾；写清各延迟从何时起算。 |
| 2 · 修在线收音及外放 | 把远端数字采集、扬声器播放参考、麦克风、送给对方的译音四路分开观察。用同一份场景清单覆盖 Auto 和 System。 | 单人回放先测远端独说、近端独说、双讲、戴耳机、混入另一应用、会后换设备。公司实会合并为一轮，验证静音旁听与外放双讲。记录远端误入我方译音次数、我方漏词、静音时对方字幕的持续性。旧计划建议的“回声处理新增延迟 P95 ≤ 30 ms”单独测量。 |
| 3 · 做两种模式的字幕与分人 | 同一批样本走面对面一支麦、在线远端混音，再测在线我方共麦。逐项打开第三字幕和本地分人，测它们各自带来的代价。 | 3–4 人约 30 句、每人通常 1–2 种语言，包含同人换语、两人同语、短句、重叠、停顿后返回和 30 秒以上长句。公布实际产生几个编号，以及逐句正确、错归、未确定、漏句、重复数；未确定和漏句都计入总数。另报语言标对率、字幕错配、首字幕与定稿延迟、RAM 和 CPU，注明机器、服务及样本数。 |
| 4 · 跑通会后与交付 | 用完整会话核对显示、历史、纪要、用量和付款方，再分别测升级包、干净包和断网。 | 一场产生超过 100 条发言，重开后核对首尾及第三语；下一场 Token 清零，上一场可查。断网恢复无错挂和重复记录；未配公司纪要服务不会扣个人额度。包内无私有配置，原配置可复用，一份诊断足以辨别失败环节。 |

**版本判定。** 当前可称 V0.3 测试版。公司 Teams 静音旁听与外放双讲、两模式的真实多人分人与流式字幕、普通办公本性能、会后数据与干净升级这几项各自保留结论。某项只有工作树接入、模拟响应或桌面回放时，就按那个证据范围报告；现场试用只需要补设备和环境才能回答的问题。

**范围仍待决定的三件事。** 面对面完整字幕、音频和纪要各自怎样沿用现有保存偏好；公司纪要服务尚未配置或权限受限时界面如何提示；长句语速实验达到什么体验才值得放进正式设置。可以先用模拟数据验收字幕与状态行为，其中涉及真实会话留存和付费账户的默认值留待明确选择。
